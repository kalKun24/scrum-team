# scrum-team

プロダクトオーナー（PO）をユーザが担い、それ以外の役割を Agent が担ってスプリントを回す Claude Code plugin である。

## 役割
| 役割 | 担い手 | 使う Skill |
|---|---|---|
| プロダクトオーナー | ユーザ | — |
| スクラムマスター | メインセッション | `run-sprint` ほか運営 Skill |
| チームの Agent | カタログから選んで編成する | `scrum-protocol` と枠ごとの Skill |

チームの Agent は固定しない。プロジェクト開始時に次の順で決める。
1. スクラムマスターがインセプションデッキの10の質問を1問ずつ PO に聞き、`.scrum/inception-deck.md` を作る。
2. スクラムマスターがデッキをもとに、同梱のカタログ（`catalog/`）から枠ごとの Agent を提案し、PO が承認する。承認された Agent は対象プロジェクトの `.claude/agents/` に取り込まれ、`.scrum/team.md` に記録される。

| 枠 | 必須 | 付与される Skill |
|---|---|---|
| implement（実装） | 必須・1〜2 | `backend-implementing` / `frontend-implementing` |
| design（デザイン） | UI がある場合 | `ui-designing` |
| code-review（コードレビュー） | 必須 | `code-reviewing` |
| security-review（セキュリティレビュー） | 必須 | `security-reviewing` |
| extra-review（専門レビュー） | 任意 | `code-reviewing` |

取り込むときに、すべての Agent に `scrum-protocol`（報告書式、ブランチ、優先順位などの共通手順）と `invisible-characters` を付ける。レビュー枠は書き込み権限を外し、モデルは sonnet に揃える。チーム編成は振り返りの Try から見直せる。

## カタログ
`catalog/` は [VoltAgent/awesome-claude-code-subagents](https://github.com/VoltAgent/awesome-claude-code-subagents)（MIT）の Agent 定義を取り込んだものである。取り込み元のコミットは `catalog/SOURCE.md`、一覧は `catalog/INDEX.md` にある。更新するときは `scripts/update-catalog.py [--ref <branch|sha>]` を実行し、差分を確かめてからコミットする。

各スプリントの成果は、PO が触れて確かめられるデモである。スプリントゴールは「スプリントの終わりに PO が何をして、何を見られるか」で書き、実行の後に「デモ準備」のフェーズを置く。デモ準備では、承認された PBI を統合ブランチにまとめ、`.scrum/demos/sprint-<N>/` に台本（`README.md`）、1コマンドで動くスクリプト（`demo.sh`）、リハーサル記録（`rehearsal.md`）を作る。

スプリント中に PO の判断が必要な場面は次の2点に限る。
1. スプリント計画：スプリントゴール、デモ台本の下書き、対象 PBI の承認
2. スプリントレビュー：デモで見たもの全体の受け入れ（受け入れたら統合ブランチをマージする）

実装・レビュー・差し戻しは Agent 同士で進める。

レトロスペクティブには、スプリントに参加した全 Agent とスクラムマスターが参加し、それぞれ KPT を出す。Problem はなぜなぜ分析で根本原因まで掘り下げる。Try は5W1H と効果の確認方法を備えた施策として、チーム合意、DoD 変更案、改善 PBI、チーム編成の変更案、plugin への改善提案のいずれかに反映する。

## 導入
```
/plugin marketplace add kalKun24/scrum-team
/plugin install scrum-team@scrum-team
```

ローカルで開発する場合は、`/plugin marketplace add <このリポジトリのパス>` で追加する。インストールせずに試すときは、対象プロジェクトで `claude --plugin-dir <このリポジトリのパス>` を実行する。この方法では、Mod のファイルを編集すると、セッション中でも自動で読み直される。

scrum ペインを使うには、Claude Code v2.1.287 以降が要る。版は `claude --version` で確かめる。

## 使い方
1. 対象プロジェクトで `/scrum-team:run-sprint` を実行する。初回はバックログの置き場を選び、続けてインセプションデッキのヒアリングに答える。デッキを見直したいときは `/scrum-team:inception-deck` を実行する。
   - GitHub Issues：`gh` CLI または GitHub MCP を使う。
   - Jira：Atlassian の MCP サーバを使う。
   - Markdown：`.scrum/backlog.md` を使う。
   - 接続が必要な場合は、その手順が案内される。
2. バックログに PBI を書く。書式は `skills/backlog-operations/` の各バックエンドのファイルに従う。
3. 再び `/scrum-team:run-sprint` を実行する。リファインメント → 計画 → 実行 → デモ準備 → レビュー → レトロスペクティブの順に進む。
4. 途中で中断しても、次に `/scrum-team:run-sprint` を実行すれば中断したフェーズから再開する。

スプリントの進み具合は、セッションの横の scrum ペインで見られる。PO が判断する場面（計画の承認、デモの受け入れ）以外は、ペインで Agent の動きを見ていればよい。

## scrum ペイン
スプリントの進行を、Claude Code のセッションの横のペインで見られる。plugin に同梱した Mod（`hooks/`）で動き、別の導入や起動は要らない。Claude Code v2.1.287 以降の端末と、Desktop アプリの Code タブで表示される（VS Code 拡張のチャット欄と `claude -p` では表示されない）。

### ペインの使い方
1. **開く**：対象プロジェクトで `claude` を起動する。`.scrum/` があれば、ペインが右に自動で開く。開かないときは、端末の幅が144桁より狭い。そのときは `/scrum` で開く。
2. **眺める**：スクラムマスターに `/scrum-team:run-sprint` で指示したら、あとはペインを見る。
   - カンバンのレーンで、各 PBI がどの段階にあるかが分かる。レーンの下に、作業中の Agent と直近の操作が出る。
   - 「Agent の会話」で、スクラムマスターからの依頼、Agent の報告、レビューの判定、Agent 同士のやり取りを追える。
   - ペインを閉じていても、プロンプトの上の帯で状況が分かる。PO の判断が要るときは、通知が出る。
3. **ペインを操作する**：Ctrl+X を押してから Tab を押すと、ペインにフォーカスが移る。最初は、カンバンの先頭の行が選ばれている。
   - ↑ ↓ で行を選び、Enter で詳細を開く。`b` で戻る。
   - 区画が狭いときは `z` で広げる。もう一度 `z` を押すと戻る。
   - Esc でプロンプトに戻る。ペインは開いたまま残る。
4. **詳しく見る**：
   - PBI の行からは、受け入れ基準と、どの Agent がいつ何をしたかの経過を見られる。
   - 会話の行からは、依頼や報告の全文を見られる。全文の画面で `a` を押すと、その Agent の記録を一覧できる。
   - レビューの差し戻しの理由は、判定の行（`✗ request-changes`）を開くと読める。
5. **デモを判定する**：レビューのフェーズに入ると、ペインの上に「PO の判定」のカードが出る。`d` でデモの詳細（動かし方、リハーサルの結果、スクリーンショット）を開く。デモを動かして確かめたら、カードで判定する。
   - 「受け入れる」を押すと、そのままスクラムマスターに伝わる。
   - 「差し戻す」を押すと、プロンプトに下書きが入る。違う点を書き足して送信する。
6. **振り返る**：`v` で読み物を開き、もう一度 `v` を押すごとに、デモ・振り返り・チーム・指標・インセプションデッキと切り替わる。`s` で過去のスプリントを選ぶと、その時点のカンバン・会話・振り返りを閲覧できる。

ペインを広げたいときは、ペインにフォーカスがある状態で Ctrl+X → ← を押す。ペインの幅が84桁以上になると、ホームが 2×2 の配置に変わる。

### 開き方
- `.scrum/` があるプロジェクトでセッションを始めると、自動で開く。端末の幅が足りない（144桁未満）ときは開かない。
- `/scrum [kanban|backlog|log|demo|retro|team|metrics|deck]` で開く。引数を付けると、その区画の拡大か読み物を開く。
- ペインの操作は Ctrl+X → Tab でペインに移ってから行う。Esc でプロンプトに戻る。

### 画面
左に会話、右のペインに次の3つの区画を置く。ペインの幅が 84 桁以上のときは、上段にバックログとカンバンを並べ、下段に会話を置く（2×2）。狭い端末でペインがプロンプトの上に入るときは、区画を数字キーで1つずつ切り替える。

| 区画 | 内容 |
|---|---|
| バックログ | 次の候補の PBI（● は ready、○ は未精査） |
| カンバン | このスプリントの PBI ごとの進行レーン（デザイン → 実装 → レビュー → PO → 完了）と、取り組んでいる Agent の直近の操作。10分以上操作が無い Agent は黄色にする |
| Agent の会話 | スクラムマスターからの依頼、Agent の発言、Agent 同士のメッセージ、レビューの判定（approve / request-changes と must・should の件数）。操作（Read・Edit・Bash など）は既定で畳む |

行を選んで Enter を押すと、詳細を開く。

| 画面 | 開き方 | 内容 |
|---|---|---|
| PBI 詳細 | バックログ・カンバンの行 | 受け入れ基準、Agent の起動の経過（担当・時間・判定）、ブランチと PR、デモの場面 |
| 発言の全文 | 会話の行 | 依頼・発言・メッセージの全文。`a`・`c` で関係する Agent の記録へ |
| Agent 詳細 | 操作の行、PBI 詳細の経過の行 | その役割の Agent の依頼・発言・やり取り・判定を時系列で並べる |
| 区画の拡大 | `z` | フォーカスのある区画をペインいっぱいに広げる。カンバンは列の表示になる |
| 読み物 | `v` | デモ（動かし方・リハーサル・スクリーンショット・判定の履歴）、振り返り、チーム、指標、インセプションデッキを順に切り替える |
| スプリントの選択 | `s` | 過去のスプリントに切り替える。過去のスプリントは閲覧のみ |

| キー | 動作 |
|---|---|
| ↑ ↓、Tab | 行やボタンを選ぶ |
| Enter | 選んだ行の詳細を開く |
| `b` | 1つ前の画面に戻る |
| `z` | 区画を拡大する。もう一度押すと戻る |
| `n` `p` | フォーカスのある区画の、次・前のページを出す。会話は新しいものが最初のページにある |
| `o` | 操作の表示を切り替える |
| `v` `s` | 読み物、スプリントの選択を開く |

レビューのフェーズでは、ペインの上に PO の判定のカードを出す。「受け入れる」は、「デモを受け入れる。」を PO の入力として送る。「差し戻す」は、プロンプトに下書きを入れる。違う点を続けて書き、送信する。

### 帯と通知
- プロンプトの上に、スプリントとフェーズ、作業中の Agent、PO 待ちの件数を1行で出す。ペインを閉じていても表示する。
- 次のときに通知を出す：レビューに入った（PO の判定待ち）、PBI の差し戻しが3回を超えた、Agent が失敗した、Agent の操作が10分以上止まっている。

### 注意
- Agent の会話は、Claude Code の会話ログ（`~/.claude/projects/<プロジェクト>/<セッション>/subagents/`）から読む。選んでいるスプリントの期間（前のスプリントの終了から、そのスプリントの終了まで）の分を出す。会話ログの書式は Claude Code の内部の形式であるため、Claude Code の版が上がると読めなくなる可能性がある。
- GitHub Issues・Jira のバックログは、スクラムマスターが書き出す `.scrum/backlog-snapshot.json` を表示する。外部サービスの認証情報は持たない（GitHub の PR の状態だけは、ローカルの `gh` で読む）。
- 表示は `.scrum/` と会話ログを読むだけで、トークンを使わない。
- Agent が作業中のままセッションが終わった場合は、次のセッションでその Agent と作業ディレクトリをペインに出し、最初の入力と一緒にスクラムマスターに伝える。スクラムマスターは、続きから進めるかやり直すかを判断する。記録は Claude Code の Mod 用の保存領域（`~/.claude/plugins/store/`）に置く。

## 権限設定
スプリント中、Agent は git とテストのコマンドを繰り返し実行する。確認のプロンプトで止まらないよう、対象プロジェクトの `.claude/settings.json` で許可しておくことを推奨する。テストと実行のコマンドはプロジェクトに合わせて書き換える。

```json
{
  "permissions": {
    "allow": [
      "Skill",
      "Agent",
      "SendMessage",
      "Bash(git:*)",
      "Bash(date:*)",
      "Bash(bash .scrum/demos/*)",
      "Bash(ls:*)",
      "Bash(mkdir:*)",
      "Bash(npm test:*)"
    ]
  }
}
```

GitHub バックエンドを使う場合は `Bash(gh issue:*)`・`Bash(gh pr:*)`・`Bash(gh label:*)` も加える。

## 対象プロジェクトに作られるファイル
```
.scrum/
  config.md              # バックエンド、容量、DoD
  team.md                # チーム編成（枠・Agent・出典・選定理由）
  inception-deck.md      # インセプションデッキ
  backlog.md             # Markdown バックエンドの場合のみ
  agreements.md          # レトロで更新されるチーム合意（Try）
  metrics.md             # スプリントごとの指標
  plugin-feedback.md     # レトロで出た scrum-team plugin への改善提案
  designs/<pbi-id>.md    # UI 仕様
  demos/sprint-<N>/      # デモの台本・実行スクリプト・リハーサル記録
  sprints/sprint-<N>.md  # スプリントの計画・進捗・結果
```

技術スタック固有の規約（言語、テストコマンド等）は、対象プロジェクトの `CLAUDE.md` に書く。Agent はそれに従う。

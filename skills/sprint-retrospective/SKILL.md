# スプリントレトロスペクティブ

## 原則
- PO の承認は求めない。結果は報告のみ行う。
- 合意は Agent の行動を変える具体的な規則として書く。「気をつける」のような行動が変わらない文は書かない。
- 合意は増やし続けない。効果が無かった合意や、DoD や Skill に取り込んだ合意は削除する。

## 手順
1. スプリントファイルの記録から次を集める。
   - 差し戻しの理由とその頻度
   - `blocked` の理由
   - PO の却下理由
   - 計画と実績のポイントの差
   - Agent が置いた仮定のうち、PO の判断と食い違ったもの
2. KPT を作る。
   - Keep：差し戻しなしで承認・受け入れされた進め方。
   - Problem：2回以上起きた差し戻し理由、却下理由、中断理由。
   - Try：Problem ごとに1つの具体的な規則。
3. Try を `.scrum/agreements.md` に追記する。各項目に対象の Agent と、追加したスプリント番号を付ける。書式：`- [developer] <規則>（Sprint <N>）`
4. 既存の合意のうち、今回のスプリントで守られても問題が再発したものは書き直し、3スプリント以上関係する事象が起きていないものは削除候補として報告に挙げる。
5. 計画と実績の差が大きい場合は、`capacity` の変更案を報告に挙げる。
6. KPT をスプリントファイルの末尾に書き、`phase` を `closed` にする。`.scrum/` の変更を `base_branch` にコミットする。
7. PO に KPT、合意の変更点、`capacity` の変更案を報告する。

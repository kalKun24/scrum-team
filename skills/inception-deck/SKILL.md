# インセプションデッキの作成

## 原則
- スクラムマスター（メインセッション）が進行し、回答はすべて PO から得る。Agent が答えを決めない。
- 1回の発言で聞く質問は1つだけとする。複数の質問をまとめて聞かない。
- 10問すべてを [questions.md](questions.md) の順に聞く。飛ばさない。
- PO が「未定」「わからない」と答えた場合は、その旨を記録して次へ進む。未定の項目は最後に一覧で示す。
- 回答が曖昧な場合は、同じ質問について深掘りを1回だけ行う。それでも曖昧なら、そのまま記録する。
- 既存のコードやドキュメントから推測できる項目（技術的な解決策など）は、調べた結果を草案として示し、PO に確認してもらう。

## 手順
1. `.scrum/inception-deck.md` があれば読む。
   - `status: agreed` の場合：見直したい項目を PO に聞き、その項目だけ手順3を行ってから手順4へ進む。
   - `status: draft` で `未回答` の項目がある場合：最初の `未回答` の項目から再開する。
   - `status: draft` で全項目が埋まっている場合：手順4から再開する。
   - 無い場合：[questions.md](questions.md) のテンプレートでファイルを作る（全項目を `未回答` にする）。
2. PO に、これから10問を1問ずつ聞くことと、所要の目安を伝え、1問目を聞く。
3. 各質問について次を繰り返す。
   1. questions.md の「聞き方」に沿って質問する。項目の意図を1文で添える。
   2. PO の回答を待つ。
   3. 回答を「記録する内容」の形に整理し、`.scrum/inception-deck.md` の該当節に書く。書いた時点で保存する。
   4. 次の発言で、整理した記録を示してから次の質問をする。PO が記録を修正した場合は反映する。
4. 10問が終わったら、要約の前に項目間の矛盾を確かめる。
   - 同じ事柄を扱う項目どうしを突き合わせる。特に、8と10の期間、7のリスクと9の優先順位、4と6の範囲を確かめる。
   - 片方が「未定」で、もう片方に値がある場合も矛盾として扱う。
   - 矛盾があれば、1つずつ PO に確認し、両方の節を回答に合わせて直す。
5. デッキ全体の要約と未定の項目を示し、PO の確認を得る。
6. 確認後、デッキ冒頭の `status` を `agreed` にし、`.scrum/` を `base_branch` にコミットする。

## デッキの使われ方
作成後、他の Skill と Agent は次のようにデッキを参照する。聞く際の意図の説明に使う。
- リファインメント：「やらないことリスト」に反する PBI を PO に指摘する。
- 計画：スプリントゴールを「なぜここにいるのか」「エレベーターピッチ」に沿わせる。
- 実行：Agent は「技術的な解決策」に従い、判断に迷ったら「トレードオフスライダー」の優先順で決める。
- レビュー：「夜も眠れない問題」に関わる変更があれば PO に示す。

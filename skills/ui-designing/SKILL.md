# UI 仕様の作成

## 原則
- 既存の UI 部品・文言・レイアウト規則を優先して再利用する。新しい部品は既存で表現できない場合のみ提案する。
- 受け入れ基準を満たす最小の UI にする。
- 開発者が迷わず実装し、レビュアーが仕様と突合できる粒度で書く。見た目の装飾より振る舞いを優先する。
- すべての操作に対し、正常・読み込み中・空・エラーの状態を定義する。
- キーボード操作、フォーカス移動、ラベル、コントラストの要件を明記する。
- 制御文字・不可視文字の表示を扱う場合は、仕様に扱い（エスケープするか、どの表記か）を明記し、書き方と確認は `invisible-characters` に従う。

## 出力書式
UI 仕様ファイルは次の節で構成する。該当しない節は「なし」と書く。

```
# <pbi-id> UI 仕様
## 対象画面・コンポーネント
<新規 / 既存の変更。既存ならファイルパス>
## 構成
<要素の配置と階層。既存部品名を使う>
## 状態
| 状態 | 表示 | 遷移条件 |
## 操作
| 操作 | 結果 | 失敗時の表示 |
## 文言
<ボタン・見出し・エラーメッセージの文言>
## アクセシビリティ
<キーボード操作、フォーカス、ラベル、読み上げ>
## 受け入れ基準との対応
| 受け入れ基準 | 満たす要素 |
## 仮定
```

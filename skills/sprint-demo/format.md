# デモの書式

`.scrum/demos/sprint-<N>/` に次を置く。Web アプリのときは、「Web アプリのデモ」の節のファイルも置く。

## README.md（台本）
```
# Sprint <N> のデモ
## ゴール
<スプリントゴール>

## 動かし方
<1コマンド。例：bash .scrum/demos/sprint-<N>/demo.sh>
<前提（必要なソフトウェア、所要時間）。Web アプリなら開く URL と、終わらせ方>

## 台本
| # | PO の操作 | 期待する結果 | PBI |
|---|---|---|---|
| 1 | <操作、または実行されるコマンド> | <見える結果> | <pbi-id> |

## 後片付け
<消すもの。隔離した環境だけを使う場合は「不要」>
```

- 場面は、PO がゴールの達成を判断できる最小の数にする。PBI ごとに少なくとも1場面を入れる。
- 画面に見えにくい変更（内部の改善、エラー処理）は、条件を再現して、観察できる結果で示す。

## 実行スクリプト
- ファイル名は `demo.sh`（bash）とする。中でプロジェクトの言語のコマンドを呼んでよい。
- 第1引数に、動かすコードのディレクトリを取る。省略時はリポジトリの直下とする。
- 一時ディレクトリを作り、デモ用のデータや設定はそこに置く。終了時に消す（`trap ... EXIT`）。
- 台本の場面ごとに `== 場面 <#>: <操作> ==` と表示してから実行し、出力をそのまま見せる。
- 第2引数に `--rehearse` を受け付ける。リハーサルでは PO の操作を待たずに最後まで進み、終わる。CLI のデモで待つ場面が無ければ、受け取って無視してよい。

## Web アプリのデモ
画面は、ヘッドレスの Chrome で台本の場面を操作して確かめ、スクリーンショットを残す。そのうえで、PO が自分で触れるようにサーバを動かしたまま待つ。

置くもの：
- `browser.mjs`：プラグインの `skills/sprint-demo/browser.mjs` の写し。デモを自己完結させるため、中身を変えずに置く。Node 22 以上と Chrome（または Chromium）で動く。
- `scenes.json`：台本の場面ごとの操作と確認。書式は `browser.mjs` の先頭のコメントのとおりである。
  - 操作：`goto`（パス）、`fill`（[セレクタ, 文字列]）、`click`、`press`（`Enter` など）、`wait`、`sleep`（ミリ秒）、`screenshot`（名前）。
  - 確認：`expect_text` / `expect_no_text`（[セレクタ, 文字列]）、`expect_count`（[セレクタ, 個数]）。場面の「期待する結果」を、少なくとも1つの確認で表す。
  - 各場面の最後に `screenshot` を置く。PO が画面で結果を見られるようにするためである。
  - セレクタは、画面の文言の変更で壊れにくいもの（`id`、`data-testid`、フォームの `name`）を使う。

`demo.sh` の流れ：
1. 一時ディレクトリにデータを置き、空いているポートでサーバを起動する（`python3 -c 'import socket; s=socket.socket(); s.bind(("127.0.0.1",0)); print(s.getsockname()[1])'` などで選ぶ）。待ち受けを始めるまで待つ（`curl -sf` で最大10秒）。
2. `node "$DEMO_DIR/browser.mjs" "$DEMO_DIR/scenes.json" <URL> <スクリーンショットの出力先>` を実行する。出力先は、`--rehearse` のときは `$DEMO_DIR/shots/$(date +%Y%m%dT%H%M%S)`（回ごとに別の場所になり、前の回の画面が残る）、それ以外は一時ディレクトリとする（PO が動かしてもリポジトリを変えないため）。出力先を表示する。
3. `--rehearse` のときは、`browser.mjs` の終了コードで終わる。それ以外は、URL と「Enter で終了する」を表示して待ち、Enter でサーバを止める。
4. Node か Chrome が無い環境では、手順2を飛ばして理由を表示し、URL を表示して待つ。リハーサルではこの状態を「未達」と記録する。

## rehearsal.md（リハーサル記録）
```
# Sprint <N> のリハーサル
- 日時：<date -Iseconds の出力>
- 回：<デモの回。初回は 1>
- 実行したコマンド：<コマンド>（コード：<統合ブランチの作業ディレクトリ>）

| # | 期待する結果 | 実際の出力（要点） | 判定 |
|---|---|---|---|
| 1 | <期待> | <出力> | 一致 / 不一致 / 未達 |

## 画面
<Web アプリのときだけ。場面ごとに ![場面 <#>](shots/<実行時刻>/<ファイル名>) を並べる>

## 出力の全文
<実行スクリプトの出力をそのまま貼る>
```

- 見せ直す（2回目以降の）ときは、前の回の `rehearsal.md` を Read で読み、同じ内容を `rehearsal-<前の回>.md` に Write してから書き直す。スクリーンショットは実行時刻ごとの場所にあるので、移さない。前の回との違いを PO が比べられるようにするためである。

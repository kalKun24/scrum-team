# デモの準備

## 原則
- スプリントの成果は、PO が触れて確かめられるデモとして示す。「やったこと」の報告ではなく、「できたもの」を見せる。
- デモは統合した状態で動かす。PBI ごとのブランチでは見せない。
- デモは一時ディレクトリなど隔離した環境で動かし、利用者のデータや設定を変えない。
- スクラムマスターが先に通しで実行し（リハーサル）、実際の出力を記録する。台本と違う振る舞いがあれば、PO に見せる前に直す。
- 書式は [format.md](format.md) に従う。

## 手順
1. スプリントファイルを読み、状態が `approved` の PBI を対象にする。1件も無ければ、`phase` を `review` にして終わる（レビューで理由を示す）。
2. 統合ブランチを作る。
   - `git worktree add <リポジトリ>/.claude/worktrees/sprint-<N> -b scrum/sprint-<N> <base_branch>` を実行する。
   - 対象の各 PBI のブランチを、計画の順に `git -C <作業ディレクトリ> merge --no-ff scrum/<pbi-id>` で取り込む。競合したら implement 枠の Agent に解消させる。
   - 作業ディレクトリでテストをすべて実行する。失敗したら implement 枠の Agent に直させ、レビュー枠の Agent に差分を再判定させる。
3. デモを作る。implement 枠の Agent に、次を含めて依頼する。
   - スプリントファイルの「デモ台本」と、対象の各 PBI の「デモでの確かめ方」。
   - format.md の書式で、`.scrum/demos/sprint-<N>/` に `README.md` と実行スクリプトを書くこと。書き先は元のリポジトリの絶対パスで指定する。
   - スクリプトは、動かすコードのディレクトリを引数に取ること（省略時はリポジトリの直下）。
4. リハーサルを行う。
   - リポジトリの直下から `bash .scrum/demos/sprint-<N>/demo.sh <統合ブランチの作業ディレクトリ>` の形で1回実行する（許可リストがこの形を前提にしている）。
   - 台本の場面ごとに、実際の出力と、期待する結果との一致を `rehearsal.md` に書く。
   - 一致しない場面があれば、原因の PBI の implement 枠の Agent に直させ、手順2のテストとレビューを経てから、リハーサルをやり直す。3回で一致しなければ、その場面を「未達」と記録して進む。
5. スプリントファイルの「記録」に統合ブランチ・作業ディレクトリ・デモの場所を書き、`phase` を `review` にする。

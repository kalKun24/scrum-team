# フロントエンド実装の基準

## UI 仕様との突合
- UI 仕様がある場合、「状態」「操作」「文言」の各行を実装に対応させる。仕様と異なる実装にする場合は理由を報告の `assumptions` に書く。
- UI 仕様が無い場合は既存画面の部品と表現に合わせる。

## 状態
- 読み込み中・空・エラーの状態を必ず実装する。
- サーバ由来のデータとローカルの UI 状態を分けて持つ。同じデータを複数箇所で重複して持たない。
- 二重送信を防ぐ。

## API 連携
- バックエンドを別の developer が並列で実装する場合、依頼に書かれた API 契約に従い、契約外のフィールドに依存しない。

## アクセシビリティ
- 操作要素はキーボードで到達・実行できるようにし、ラベルを付ける。
- フォーカスの移動を UI 仕様どおりにする。

## テスト
- 受け入れ基準ごとに、利用者の操作を起点としたテストを書く。
- エラー状態の表示をテストする。

# 不可視文字の扱い

## 原則
- Write / Edit ツールの引数に「バックスラッシュ + u + 16進4桁」の表記を書くと、実際の文字に変わってファイルに入る。そのため、この表記をそのまま書かない。
- 不可視文字は読み返しても見えない。混入の有無は目視ではなく、下記の Grep で判定する。

## 書き方
- 文書（UI 仕様、スクラムの記録、バックログ）：文字は `U+202E` のようにコードポイント名で書く。エスケープ表記そのものを示す必要がある場合は、バックスラッシュを `U+005C` と書いて表記を分解する。
- コード・テスト：文字コードから文字を作る言語の機能を使う（例：Python の `chr(0x202E)`）。文字列リテラルにエスケープ表記を残す必要がある場合は、バックスラッシュを二重にする。

## 確認
1. 不可視文字を扱う内容を書いた直後、報告やコミットの前に、書いたファイルを Grep で検索する。パターンは次のとおりとする。
   ```
   [\x{0000}-\x{0008}\x{000B}\x{000C}\x{000E}-\x{001F}\x{007F}-\x{009F}\x{061C}\x{200B}-\x{200F}\x{202A}-\x{202E}\x{2060}\x{2066}-\x{2069}\x{2028}\x{2029}\x{FEFF}]
   ```
2. 0件でなければ直す。意図して入れた文字だけが残る場合は、その行に注記を付け、行番号を報告する。
3. 報告（implement・design の報告、レビュアーの `tests` / `checks` 欄）に件数を書く。

## レビューでの確認
- 不可視文字を扱う PBI では、差分全体と、対象 PBI の UI 仕様に同じ Grep をかける。
- 注記の無い生の不可視文字が見つかった場合は `must` とする。
